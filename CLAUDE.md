# СтройAI — рабочая версия с бэкендом

Инструкция для Claude Code. Читай её целиком перед любой работой и возвращайся к ней перед завершением каждого этапа.

## 0. Главное правило: всё проверяй сам

Задача не считается сделанной, пока ты сам не проверил результат командами и не показал вывод. «Должно работать» — не ответ.

После **каждого** изменения кода:

1. **Бэкенд:** `ruff check`, `mypy` (или `pyright`) — без ошибок; `pytest` — все тесты зелёные; новые эндпоинты покрыты тестами (успех, ошибка валидации, отказ по правам).
2. **Миграции:** `alembic upgrade head` на чистой базе, затем `alembic downgrade -1` и снова `upgrade head` — всё проходит.
3. **Фронтенд:** `npm run typecheck` и `npm run build` — без ошибок.
4. **Права:** тест-матрица «роль × эндпоинт» — каждый эндпоинт проверен для каждой роли: разрешённые получают 2xx, остальные — 403. Матрица берётся из `shared/permissions.json`.
5. **Сквозная проверка (e2e, Playwright):** ключевые сценарии этапа проходят в браузере **через реальный домен и Caddy**, а не только на localhost. В консоли браузера — 0 ошибок.
6. **Сервер:** после деплоя — `docker compose ps` (все healthy), `docker stats --no-stream` (память наших контейнеров в лимитах), `curl -I https://<домен>/api/health` → 200, логи без ошибок (`docker compose logs --tail=100`).
7. **Чужие сервисы целы:** после любых действий на сервере проверь, что n8n и остальные контейнеры работают (`docker ps`, `curl -I` на домен n8n). Мы на сервере в гостях.

Если что-то не проходит — чини и проверяй заново. Не скрывай падающие тесты, не помечай их `skip` без объяснения Петру. В конце этапа пиши короткий отчёт: что сделано, какие проверки прошли (с цифрами), что осталось, что нужно от Петра.

## 0.1. Режим работы: Claude Code в веб-версии

- Ты работаешь в облачной среде с этим GitHub-репозиторием. **Доступа к серверу 138.124.108.18 у тебя нет.**
- Всё, что можно проверить у себя, проверяй у себя: тесты бэкенда (PostgreSQL поднимай локально в среде, если Docker недоступен — нативный postgres), сборку фронтенда, e2e Playwright против локально запущенных api + фронтенда. Если чего-то в среде нет (Docker, браузер) — установи; не получилось — скажи Петру прямо, что именно не проверено.
- **Деплой и проверки на сервере** выполняет Пётр по твоим командам: давай по 1–2 готовых блока для вставки, жди вывод, анализируй, давай следующий шаг. Не проси его править файлы руками — только команды.
- Изменения — в ветки с понятными коммитами; в `main` — когда этап проверен. На сервере код обновляется через `git pull` в `/opt/stroyai`.
- Когда этап 1 заработает, предложи Петру автодеплой через GitHub Actions (SSH-ключ в секретах репозитория, на сервере `git pull && docker compose up -d --build` + проверка `/api/health`, при ошибке — откат на предыдущий коммит). Включать только с его согласия.

## 2. Первый релиз — состав

**Входит:**
- Вход по логину и паролю, роли и права, управление сотрудниками.
- Главная панель (показатели и предупреждения по данным из базы).
- Проекты: объекты, этапы, графики, задачи, лента событий, уведомления.
- Снабжение и склад: материалы, поставщики, заявки (согласование), заказы, приход, остатки, перемещения, списание.
- Сметы: загрузка (в т.ч. выгрузка ГРАНД-Сметы xlsx), версии, сверка, корректировка (исключение работ / изменение объёмов → новая версия).
- Выполнение: КС-2/КС-3, подписание.
- Себестоимость: текущие объекты, расчёты новых объектов (укрупнённо / по аналогу).
- ПТО: 15 видов актов, версии, согласование; документы о качестве (сертификаты, паспорта) с входным контролем и поиском в архиве компании; фотофиксация с техническими правками; исполнительные схемы.
- Чертежи: DXF (просмотр, измерения, правки, версии, расчёты) + **интеграция с AutoCAD: загрузка DWG и выгрузка в DWG** через серверный конвертер.
- Выгрузки: Word, PDF (печать), Excel (.xlsx), CSV, DXF.

**Не входит (следующие этапы), в рабочей сборке скрыть из меню:** Переписка (почта через n8n), AI-ассистент, База знаний. Код прототипа по ним не удалять — понадобится.

**Пользователи:** до 10 человек на старте.

## 3. Роли и доступ

- При первом запуске создаётся **одна учётная запись — директор** (логин и пароль из `.env`: `DIRECTOR_LOGIN`, `DIRECTOR_PASSWORD`, `DIRECTOR_NAME`). Других пользователей и демо-данных в рабочей базе нет.
- **Директор сам заводит сотрудников**: ФИО, должность, логин, пароль, роль (РП, ПТО, сметчик, снабженец, прораб, бухгалтер), назначенные объекты. Может сменить роль, сбросить пароль, заблокировать. Пароль при выдаче — временный, при первом входе сотрудник обязан сменить.
- Роль `admin` в интерфейсе выдачи не показывать (служебная, для Петра — создаётся только командой CLI).
- Матрица прав — **`shared/permissions.json`** (генерируется из `frontend/src/domain/permissions.ts` командой `npm run gen:permissions` в `frontend/`). Бэкенд читает этот файл; права проверяются **на сервере** для каждого запроса. Фронтенд прячет кнопки, но это не защита.
- Видимость объектов: директор, админ, бухгалтер видят все; остальные — только назначенные (`project_ids`). Проверять на сервере во всех списках и по id.
- Безопасность: пароли — bcrypt/argon2; сессия — JWT в httpOnly + Secure + SameSite=Lax cookie (или серверные сессии); ограничение попыток входа (например, 5 за 10 минут на логин+IP); журнал действий (кто, что, когда) для входа, выдачи прав, подписаний, удалений.

## 4. Стек и архитектура

- **Бэкенд:** Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, Pydantic v2, psycopg 3, pytest, ruff, mypy/pyright.
- **База:** PostgreSQL 17 в своём контейнере (отдельно от чужих баз на сервере). Настройки под малую память (shared_buffers ~128MB).
- **Файлы:** на диске сервера в volume (`/data/files`), в базе — метаданные. Абстракция хранилища, чтобы позже переключить на S3. Лимит размера загрузки, проверка типа файла, имена файлов на диске — сгенерированные (не пользовательские).
- **Фронтенд:** текущий React; слой данных — TanStack Query + fetch-клиент к `/api`. zustand persist убрать для бизнес-данных (оставить только UI-настройки: тема). Демо-сид (`frontend/src/data/*`) в рабочую сборку не попадает.
- **Конвертер DWG ↔ DXF:** отдельный контейнер, запуск по требованию с таймаутом и лимитом памяти. Кандидаты: **LibreDWG** (`dwg2dxf`/`dxf2dwg`, GPL) и **ODA File Converter** (бесплатный, проверь условия лицензии). Перед выбором — сравни на нескольких реальных DWG (попроси у Петра) и опиши Петру результат. Если конвертация не удалась — честное сообщение пользователю, а не пустой чертёж.
- **Расчёты:** доменные функции из `frontend/src/domain/*` остаются для отображения, но **важные проверки дублируются на сервере** (см. п. 6).
- **Docker Compose:** сервисы `db`, `api`, `web` (nginx: статика фронтенда + прокси `/api` → `api`), `converter`. У каждого — `mem_limit`, `restart: unless-stopped`, healthcheck.

Структура репозитория:
```
frontend/        — React-приложение (из прототипа)
backend/         — FastAPI: app/, alembic/, tests/
shared/          — permissions.json (общий для фронта и бэка)
deploy/          — docker-compose.yml, nginx.conf, .env.example, backup.sh, Caddy-блок
docs/            — заметки, legacy-e2e (сценарии прототипа)
```

- Подключение: контейнер `web` подключается к внешней сети `n8n_data_default` с алиасом, например `stroyai-web`. В Caddyfile **дописать** блок (перед правкой — бэкап файла с датой):

  ```
      encode gzip
      reverse_proxy stroyai-web:80
  }
  ```
  Проверка и применение: `docker exec caddy-n8n caddy validate --config /etc/caddy/Caddyfile` → `docker exec caddy-n8n caddy reload --config /etc/caddy/Caddyfile`. Убедиться, что n8n после этого открывается.
- **Домен:** `app.stroika.petr-ai.ru` (A-запись на 138.124.108.18 в Beget — Пётр добавляет; проверь `dig +short app.stroika.petr-ai.ru` перед выпуском сертификата).
- Код на сервере: `/opt/stroyai` (git clone этого репозитория; для приватного репо — deploy key только на чтение). Секреты — только в `deploy/.env` (в git не коммитить, в репо — `.env.example`).
- **Бэкап:** ежедневно (cron) `pg_dump` + архив файлов в `/opt/stroyai/backups`, хранить 14 дней. **Проверь восстановление** из бэкапа на отдельной временной базе — без этого этап не закрыт.
- Любые действия, которые могут затронуть чужие сервисы или удалить данные, — сначала спроси Петра.

## 6. Правила, которые нельзя потерять (проверяются на сервере)

- **Склад:** остатки меняются только транзакцией вместе с записью движения; остаток не может уйти в минус; параллельные списания не должны «продать» одно и то же (блокировка строки / проверка в транзакции).
- **КС-2:** объём за период ≤ остатка по смете (с учётом подписанных КС-2 той же сметы за прошлые периоды). Подписанные КС-2 неизменяемы. Подписывают только роли с `execution.approve`.
- **Сметы:** корректировка не меняет исходную версию — всегда новая версия. Исключённые позиции не входят в итог, сверку и КС-2.
- **Версии (акты ИД, чертежи, фото):** только добавление новых версий; оригинал не перезаписывается и не удаляется.
- **Фото:** только технические правки (кадр, поворот, пометки, штамп, размытие, яркость). **Генеративное изменение содержимого снимков (убрать/добавить людей, дорисовать каски и т.п.) не делаем** — фото являются доказательствами для технадзора и ГСН. Решение согласовано с Петром.
- **Исполнительные схемы:** факт — только из съёмки геодезиста (CSV или ввод); допуски вводит пользователь, система их не подставляет; **демо-съёмку сохранить в ИД нельзя**.
- **Документы о качестве:** новый документ → «ожидает входного контроля»; отклонение — только с причиной; паспорт на партию из открытых источников не берётся — запрос поставщику.
- **Шаблоны актов и КС-2/КС-3** — демонстрационные, с пометкой «сверить с действующими требованиями (приказ Минстроя России № 344/пр)». Пометку не убирать, пока заказчик не даст утверждённые шаблоны.
- **Себестоимость новых объектов:** ставки — демо; пометка в интерфейсе остаётся. Расчёты по чертежу — подсчёт объёмов, не прочностные расчёты.

## 7. Этапы и критерии готовности

Каждый этап заканчивается деплоем на сервер, полной проверкой (п. 0) и отчётом Петру.

1. **Каркас.** Репозиторий, Docker Compose (db/api/web), Alembic, `/api/health`, вход/выход/смена пароля, директор из `.env`, управление сотрудниками (создание, роль, объекты, сброс пароля, блокировка), журнал действий, ограничение попыток входа, деплой на `app.stroika.petr-ai.ru` через Caddy, бэкап + проверка восстановления. Фронтенд: страница входа, «Сотрудники» на API, остальные разделы в рабочей сборке пока скрыты.
   *Готово, когда:* директор входит по домену с HTTPS, создаёт сотрудника с ролью, тот входит, меняет временный пароль и видит только свои разделы; тест-матрица прав зелёная; бэкап восстанавливается.
2. **Проекты, снабжение, склад** на API (с серверными правилами склада; тест на конкурентное списание).
3. **Сметы, КС-2/КС-3, себестоимость** на API (загрузка xlsx ГРАНД-Сметы, версии, корректировка, сверка, КС-2 с серверной проверкой остатка, подписание, выгрузки Excel).
4. **ПТО и чертежи** на API: файлы на сервере, версии, документы о качестве, фото, исполнительные схемы, DXF, конвертер DWG ↔ DXF.
5. **Запуск:** перенос реальных объектов Аслана (импорт), проверка на реальных DWG и сметах, мониторинг (место на диске, память), инструкция пользователя.
