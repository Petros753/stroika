# СтройAI — кликабельный прототип ERP для строительной компании

Демонстрационный прототип: React 18 + TypeScript + Tailwind CSS + Lucide + Recharts + React Router.
Данные хранятся в `localStorage` браузера, бэкенда нет. Интерфейс — на русском языке.

## Запуск

```bash
npm install
npm run dev      # режим разработки, http://localhost:5173
npm run build    # production-сборка в dist/ (открывается и с file://, base = './')
npm run preview  # предпросмотр сборки
```

Сброс демо-данных — кнопка в боковой панели (значок «обновить») или очистка `localStorage` (ключ `stroyai-demo-v1`).

## Что реально работает, а что — демонстрация

**Работает по-настоящему:** вся бизнес-логика и расчёты, права по ролям, сверка смет, разбор Excel/CSV/XML,
экспорт SVG, CSV (план чертежа, спецификация, смета, отчёт сверки), Word (.doc, HTML-формат) и печать в PDF для документов ИД и КС-2/КС-3.

**Демонстрация (честно помечено в интерфейсе):**
- DWG, DXF и PDF для чертежей — окна-пояснения, файлы не создаются.
- «PDF» отчёта сверки смет — окно-пояснение (реальный отчёт — CSV).
- Разбор PDF-смет — имитация распознавания.
- Индексация базы знаний — имитация; поиск идёт по названиям.
- AI-ассистент и AI CAD — детерминированные правила по ключевым словам, **не языковая модель**.
- Ставки расчёта себестоимости новых объектов — демонстрационные укрупнённые показатели (в рабочей версии — НЦС Минстроя и база завершённых объектов).
- Выгрузка в Excel (.xlsx): все акты ИД, КС-2 (итоги формулами), КС-3.
- Поиск документов о качестве: архив компании (реальный поиск по другим объектам) + реестр Росаккредитации и сайты производителей (в прототипе — демо-результаты; в рабочей версии — n8n на сервере); паспорта на партию — письмо-запрос поставщику через «Переписку».
- Исполнительные схемы: точки разбивки из осей проектного DXF + данные съёмки (CSV или ввод) → отклонения, допуски (задаёт пользователь), схема со штампом, DXF/PDF, сохранение в ИД с графической частью. Демо-съёмку сохранить в ИД нельзя.
- «Распознавание» скана сертификата — демо по имени файла (в рабочей версии — Docling + OCR). Требования к документам о качестве по материалам — демо-правила.
- Почта в демо не подключена: входящие — демо-письма и имитация, «отправка» только регистрирует письмо. В рабочей версии — n8n: IMAP → классификация LLM → черновик с RAG → согласование в СтройAI → SMTP.
- DWG не читается в браузере: в рабочей версии сервер конвертирует DWG → DXF (ODA File Converter / LibreDWG). Расчёты по чертежу — подсчёт объёмов по геометрии, не прочностные расчёты.
- Фото, сканы и DXF хранятся в IndexedDB этого браузера (в рабочей версии — S3).
- Формы КС-2/КС-3 — приближены к унифицированным, но **не юридически проверенные бланки**.
- Шаблоны ИД — демонстрационные, **не юридически проверенные формы**; оговорка есть в каждом документе.

## Принятые допущения

- «Сегодня» зафиксировано как **14.11.2026** (`src/lib/date.ts`, `TODAY`), чтобы просрочки и отставания были одинаковыми в любой день. В рабочей версии заменить на `new Date()`.
- Плановый прогресс считается по датам этапов с весами по плановой стоимости; перерасход = фактические затраты − освоенный объём; прогноз стоимости = факт / прогресс; «отстаёт» — от 5 п.п.
- Предупреждения AI не хранятся, а вычисляются правилами по текущим данным.
- Директор и руководитель проекта получили права на правку чертежей и создание документов ИД; загружать сметы может сметчик и администратор, сверять — также директор, руководитель проекта, администратор.
- Исправление ответа AI попадает в базу знаний только от сотрудника с правом управления базой; от остальных — уходит в журнал на проверку. Автоматического дообучения нет.
- Размерность чертежа: 1 условная единица = 10 см; план условный (двухэтажное здание).

## Архитектура и путь к рабочей версии

```
src/
  domain/   чистая бизнес-логика без React: calc, analysis, estimates, assistant, cad, cadAi, permissions
  data/     демо-данные (seed), сметы, чертёж
  store/    zustand + persist (localStorage); действия store = будущие API-вызовы
  pages/, components/   интерфейс
```

Слой `domain/` не зависит от UI и переносится на бэкенд почти без изменений. Рекомендуемый целевой стек:

- **Бэкенд:** FastAPI, PostgreSQL 17, SQLAlchemy/Alembic, Redis (очереди и кэш), S3-хранилище файлов.
- **Права:** RBAC на сервере; матрица `PERMISSIONS` отдаётся из `/me/permissions`, фронтенд только отображает.
- **RAG:** разбор файлов → фрагменты → эмбеддинги → pgvector; ответы со ссылками на источники; исправления проходят проверку.
- **Чертежи:** интеграция с Autodesk Platform Services (Model Derivative / Design Automation) для DWG/DXF; парсер на бэкенде.
- **Сметы:** разбор экспорта ГРАНД-Сметы (XML/XLSX), OCR для PDF.
- **Инфраструктура:** Docker Compose, Nginx, CI с `tsc` и сборкой.
